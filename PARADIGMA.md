## 1. MÉTODOS (Técnicas Sistemáticas de Desarrollo)
- **Modelo de Proceso:** Desarrollo Incremental, debido a que el proyecto se puede desarrollar por etapas. Primero se realizará la recopilación y comprensión de los datos, posteriormente su limpieza y preparación, después el análisis y finalmente la presentación de resultados y conclusiones.
- **Técnicas de Análisis y Especificación:** Técnicas de análisis de datos para identificar las características, necesidades y posibles problemáticas. Se definirán los objetivos del análisis, las variables de interés y los resultados que se esperan obtener.
- **Técnicas de Validación:** Se realizaran revisisones de los datos, comprobaciones de consistencia y validación de los resultados obtenidos. Además, se llevarán a cabo revisiones entre los integrantes del equipo para identificar errores en el procesamiento, análisis o interpretación de la información.

## 2. HERRAMIENTAS (Soporte Automatizado CASE y Entorno de Desarrollo)
- **Entorno Integrado (IDE):** Visual Studio Code para el desarrollo de scripts y procesamiento de los datos.
- **Control de Versiones y SCM:** Git y GitHub para almacenar el código del proyecto, llevar un control de versiones y facilitar el trabajo colaborativo entre los integrantes.
- **Analizador Estático de Código (Linter):** Pylint para analizar el código Python, identificar errores potenciales, malas prácticas y problemas de estilo antes de ejecutar o integrar los cambios.
- **Gestión de Tareas:** Tablero Kanban en GitHub Projects.

## 3. PROCEDIMIENTOS (Estructura y Normativa Organizacional)
- **Formato de Commits:** Se utilizarán mensajes sencillos para identificar los cambios realizados en el proyecto, como feat: cuando se agregue algo nuevo, fix: cuando se corrija un error, docs: cuando se actualice la documentación y refactor: cuando se realicen mejoras en el código.
- **Estrategia de Ramas (Branching):** Prohibido hacer push directo a `main`. Todo
cambio se realiza en `feature/*` y requiere Pull Request.
- **Política de Code Review:** Todo Pull Request requiere aprobación escrita de al menos
1 integrante antes del Merge.
